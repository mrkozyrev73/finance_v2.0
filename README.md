# Доход — учёт доходов и финансов

Мобильная PWA на чистом HTML/CSS/JS. Сборки нет: `index.html` самодостаточен,
рядом лежат только манифест, service worker и иконки.

```
index.html                209 КБ   всё приложение целиком
manifest.webmanifest               имя, иконки, standalone
sw.js                              офлайн-кеш оболочки
icon-192 / icon-512 / icon-maskable-512 / apple-touch-icon
```

## Как запустить

**Быстро посмотреть** — открыть `index.html` двойным кликом. Работает всё,
кроме установки на домашний экран и офлайн-кеша (service worker из `file://`
не регистрируется — это ограничение браузеров, не приложения).

**По-настоящему** — положить папку на любой https-хостинг (GitHub Pages,
Netlify, Vercel, свой nginx) и открыть на телефоне. Safari: «Поделиться» →
«На экран Домой». Chrome: меню → «Установить приложение».

Локально с service worker:

```bash
cd <папка>
python3 -m http.server 8080
# затем http://localhost:8080 — localhost считается защищённым источником
```

## Категории

Стартовый набор из 13 категорий задан в `src/js/10-store.js` (`DEFAULT_CATEGORIES`),
каждой присвоен свой цвет — обход цветового круга в одном регистре насыщенности,
чтобы соседние сектора кольца различались.

Обновление набора завязано на `CATEGORIES_VERSION`. При открытии более старой
версии данных срабатывает `upgradeCategories`:

- набор «из коробки» (все названия из первой версии) заменяется на новый,
  а доходы, которые на него ссылались, переезжают в «Прочее» — ничего
  не осиротеет;
- свои категории (переименованные или добавленные) не трогаются никогда,
  ставится только отметка версии;
- повторные запуски ничего не дублируют.

Заменить набор вручную в любой момент: Настройки → Категории доходов →
«Вернуть набор по умолчанию» (старые уедут в корзину).

## Быстрый выбор категории

В форме дохода под выпадающим списком идёт строка категорий: недавно
использованные впереди (порядок считает `Data.recentCategories()` по времени
создания доходов). Строка одна, листается пальцем вбок; справа появляется
градиент-подсказка, если есть что листать. Выбор через список подкручивает
строку к нужной категории.

Метка — точка цветом самой категории, выбранная подсвечивается фоном того же
цвета на 12%. Ни рамок, ни «таблеток»: цвет здесь несёт смысл, а не украшает.

## Статусы доходов

Кружок слева в строке дохода — переключатель: тап отмечает доход полученным,
повторный тап возвращает в ожидаемые. Тост даёт «Отменить». Тап по остальной
части строки открывает редактирование, свайп влево — «Изменить» и «Удалить».

## Финансы

Добавление вкладов и кредитов — одной зелёной кнопкой «+» в шапке экрана;
на самом экране кнопок добавления нет, чтобы список читался сплошным
и не рвался пунктирными прямоугольниками. Пустая секция подсказывает,
где искать «+».

Внизу секции кредитов — итоговая строка «Платежей в месяц»: своя карточка,
сумма 21 px против 18 px в карточках, чтобы читалась именно как итог.

Карточка кредита показывает оставшийся срок и переплату до конца
(аннуитет, `Loan.months` / `Loan.overpay`). Калькулятора досрочного
погашения нет — убран вместе с разделом досрочных платежей.

## Данные

Всё хранится в `localStorage` под ключом `dohod.state.v1`. Каждая запись несёт
`updatedAt` и `deletedAt`, поэтому удаление мягкое (корзина, восстановление),
а слияние двух устройств идёт позаписно: побеждает бо́льший `updatedAt`
у каждой записи, а не «кто последним сохранил документ целиком».

Резервных копий, выгрузки и снимков в приложении нет — единственный
механизм сохранности данных это синхронизация.

## Синхронизация с Supabase

### Один раз в проекте

1. Создать проект на supabase.com.
2. SQL Editor → выполнить схему (она же в приложении, кнопка «Скопировать SQL»):

```sql
create table if not exists public.app_state (
  user_id    uuid primary key references auth.users(id) on delete cascade,
  data       jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);

alter table public.app_state enable row level security;

create policy "own row read"   on public.app_state
  for select using (auth.uid() = user_id);
create policy "own row insert" on public.app_state
  for insert with check (auth.uid() = user_id);
create policy "own row update" on public.app_state
  for update using (auth.uid() = user_id) with check (auth.uid() = user_id);

-- Нужно для мгновенного обмена между устройствами
alter table public.app_state replica identity full;
alter publication supabase_realtime add table public.app_state;
```

3. Authentication → Providers → Email → **Confirm email = off**. Без этого при
   регистрации сессия не выдаётся и вход повиснет в ожидании письма.

### Адрес проекта: вписать один раз, чтобы не спрашивал

Чтобы на телефонах остались только логин и пароль, адрес проекта вшивается
в файл. Одной командой:

```bash
node configure.js https://xxxx.supabase.co <anon-public-key>
```

Оба значения — в Project Settings → API. Команду можно повторять сколько
угодно раз: она заменяет значения, а не дописывает. Если правите исходники,
положите рядом `supabase.config.json`:

```json
{ "url": "https://xxxx.supabase.co", "key": "anon-public-key" }
```

— и `node build.js` вошьёт их сам. Либо вручную: строки `SUPABASE_URL`
и `SUPABASE_ANON_KEY` в начале скрипта внутри `index.html`.

Ключ anon публичный по своей природе: он в любом случае уходит в браузер,
а доступ к данным ограничивают политики RLS выше. Держать его в файле не
опаснее, чем вводить руками. Если адрес не вписан, приложение спросит его
само при первом подключении.

### Вход

На первом телефоне: Настройки → Синхронизация → «Войти» → логин, пароль,
кнопка **«Создать»**. На втором — тот же логин и пароль, кнопка **«Войти»**.

Supabase Auth хранит учётку по адресу почты, поэтому логин без «@»
дополняется техническим доменом: `anton` → `anton@dohod.app`. Никакая почта
не задействуется — отсюда и требование отключить подтверждение адреса.
Логин пишется латиницей.

### Как достигается «мгновенно на двух телефонах»

- Отправка идёт **на первом же изменении**, без ожидания хвоста; серия быстрых
  правок схлопывается в один запрос окном 250 мс.
- Приём применяет данные **прямо из realtime-события**, без второго похода
  в базу. Отсюда `replica identity full` в схеме: без него Postgres пришлёт
  в событии не всю строку.
- При возврате приложения из фона и при появлении сети делается догоняющий
  запрос: телефон засыпает, вебсокет умирает, полагаться только на него нельзя.
- Если канал отвалился, он пересоздаётся через 1,5 с и следом идёт `pull`.
- Своё же эхо отбрасывается по `updated_at` — циклов нет.
- Между вкладками одного браузера состояние расходится через
  `BroadcastChannel`, без обращения к сети.
- Правки с двух устройств сливаются позаписно, поэтому одновременные
  изменения разных записей не затирают друг друга.

Замер в `sync-check.js` (два независимых профиля браузера, мок Supabase с SSE):
правка долетает до второго устройства за 40–70 мс.

Anon key публичный: доступ к строкам ограничивают политики RLS выше,
каждый видит только свою.

## Что где в коде

`index.html` собран из `src/` скриптом `build.js`:

```
src/styles.css        дизайн-система: токены, компоненты, движение
src/body.html         разметка оболочки и спрайт иконок
src/js/00-util.js     формат денег и дат, проекция инерции, резина
src/js/10-store.js    состояние, localStorage, слияние, журнал действий
src/js/20-shell.js    вкладки, шапка месяца, модальные листы, тосты
src/js/30-home.js     свайп-жест, галочка статуса, список доходов, форма
src/js/40-stats.js    аудит, динамика, кольцевая диаграмма, структура
src/js/50-fin.js      сейф, вклады, кредиты, срок и переплата по кредиту
src/js/60-settings.js категории, регулярные, история, корзина, ранее заработанное
src/js/70-sync.js     Supabase: конфиг, вход, pull-merge-push, realtime, догон

```

Пересборка: `node build.js`. Проверки:

```
node check.js         23 пункта чек-листа в живом Chromium
node smoke.js         все модальные экраны, формы, повторы, галочка статуса
node sync-check.js    два «телефона» на мок-Supabase: обмен, слияние, догон
node builtin-check.js вшитый адрес: в интерфейсе только логин и пароль
node ui-check.js      кольцо структуры и строка категорий
node migrate-check.js обновление с первой версии без потери данных
```

## Принципы, на которых держится стабильность интерфейса

- DOM создаётся один раз, дальше меняются только значения внутри узлов.
  Смена месяца не пересобирает экран и не двигает прокрутку.
- Списки сверяются по `id`: существующие карточки переиспользуются,
  переставляются только те, у кого поменялась позиция.
- Диаграммы живут в слотах фиксированной высоты (график 252 px, кольцо 152 px),
  переключение режимов — `opacity`/`visibility`, а не удаление узлов.
- Раскрытие категории — `grid-template-rows: 0fr → 1fr` внутри карточки,
  без модалок и без сдвига соседей.
- Перерисовки схлопываются: вызов во время отрисовки не запускает вторую,
  а откладывается до конца текущей.
- Свайп: гистерезис 10 px до захвата направления, трекинг 1:1, резина за
  границами, на отпускании — проекция инерции, а не пороговое сравнение.
- Движение 160–240 мс, только `transform` и `opacity`,
  `prefers-reduced-motion` уважается.
